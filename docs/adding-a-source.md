# Adding a source: the path every source in this repository took

> Repo path: `docs/adding-a-source.md`
> Governing decisions: [D-15](decisions/decision-register.md#d-15) as
> amended by Amendment T (a committed, pinned extract per source),
> [D-29](decisions/decision-register.md#d-29) as amended by Amendment U
> (one mapping contract per category, the engine's fan-in),
> [D-41](decisions/decision-register.md#d-41) (conformance in silver,
> co-location in gold, service through the typed surfaces).

Nothing in the pipeline knows the demo's sources by name. Bronze lands
whatever `ingestion.sources` lists, the profiler measures whatever
`profiling.targets` names, the engine emits a category for every
mapping contract in `engine.mapping_contracts`, the context compiler
and the serving layer read the star, and the gates hold every contract
the same way. The seven demo extracts went through the steps below,
and so did a source that is not in the demo: the World Bank GDP series
(a country-by-year table from a different domain), added by following
this page in a fresh clone of v1.1.0. That run took under fifteen
minutes of wall time, touched eight files by hand, and ended with
a four-category star green at every gate (`PASS=389`, `make audit-gold`
`PASS=83`, the manifest gate, the unit lane at 553 and the local lane
at 76) and the new category served with its own subject and expert
context. Its files are the worked example quoted here.

The shape of the work: one file to fetch, four entries to declare,
two contracts to write, one model, and a paste into the star contract.
Everything else is generated by a command and reviewed. The reasoning
the demo sources took at each of these steps, join by join, is in
[docs/sources-explained.md](sources-explained.md); the operator's
manual for everything around them is [docs/operating.md](operating.md).

## 0. Before you start

- Pick a public dataset with a license that allows redistribution, and
  a publisher artifact that will not move under you: a file at a
  commit SHA on GitHub, a versioned release, a dated archive. The
  fetch script pins that artifact and its raw digest; a publisher
  revision then refuses loudly instead of re-extracting silently
  (Amendment T).
- Keep the committed extract under 10 MB (20 MB for an event source;
  see step 1). The window is code in the fetch script.
- Choose the names once: the dataset name (the bronze table), the
  silver table `silver_<dataset>`, and the category name. A category
  name must never equal a dbt model name (rule 9, F-12): `world_gdp`
  is the category, `silver_world_gdp` the table.
- The star needs a time column of `logicalType: date` on the silver
  table (a DATE or TIMESTAMP): a source keyed by year derives
  `period_start` as the first day of the year, and the mapping declares
  `timeGrain: year`. Grains run from `minute` to `year` on one conformed
  calendar (D-17 Amendment R).
- `make doctor` is green and the two exports it prints are set in the
  shell.

## 1. The fetch script and the extract (Amendment T)

Copy `scripts/fetch_ourairports_airports.py` to
`scripts/fetch_<dataset>.py`, set `SOURCE`, the pinned `COMMIT` and
`SOURCE_URL`, the window logic, and `MAX_BYTES`. Leave `RAW_SHA256`
as `None` for the first run:

    uv run python scripts/fetch_world_gdp.py

    downloading https://raw.githubusercontent.com/datasets/gdp/36d761dc.../data/gdp.csv
    raw gdp_36d761dc5617.csv: sha256 8d84ef6b... (unpinned; copy it into RAW_SHA256 once reviewed)
    OK world_gdp: 13979 rows, 562768 bytes, extract sha256 bb704e8c...

Copy the raw digest into `RAW_SHA256`, write
`data/samples/<dataset>/README.md` in the shape of
`data/samples/ourairports_airports/README.md` (source, citation with
the pin, license, retrieval line with the raw digest, window, rows and
bytes and the extract digest, the normalization rule, any landing note,
the regenerate command), and run the script again: the second run
must print `matches the pinned value` and leave the extract
byte-identical. The committed-samples gate then holds the README to the
bytes:

    uv run pytest -q tests/test_committed_samples.py

An extract over 10 MB is an event source under the 20 MB cap: name its
dataset in `EVENT_SOURCES` in `tests/test_committed_samples.py` and in
`tests/test_ingest_config.py`, and say so in the README.

## 2. Bronze: the landing and the profile

Declare the source once in `config/default.yaml` under
`ingestion.sources` (the dataset name, the committed CSV, and reader
options: pin code columns to `str` so leading zeros and codes survive
inference, and set `keep_default_na` false when a value collides with
pandas' missing markers, F-50), and once more under `profiling.targets`
as `{schema: bronze, table: <dataset>}`. Add the bronze table to
`transform/models/bronze/sources.yml` with a row per column as landed
(no renames, no casts: casting is a silver decision). Then:

    make ingest
    make profile ONLY=bronze.<dataset>

`make ingest` lands every listed source (replace semantics) and prints
the counts; the profile writes
`profiles/bronze.<dataset>/v0001.json` and prints its content hash.
Read the profile before you write the contract: the null rates, the
distinct counts, the min and max, the samples. The World Bank series
turned out to mix 214 economies with 48 aggregates under one column,
which is the kind of fact the contract exists to say.

## 3. Silver: the cleanup contract, the model, the properties

The contract comes first (rule 6). With a key in the shell,
`make propose-silver SOURCE=<dataset>` drafts it from the profile into
the outbox for your review; without one, copy the closest committed
cleanup contract (`contracts/silver_nyc_airlines.odcs.yaml` is the
smallest) to `contracts/silver_<dataset>.odcs.yaml` and write it from
the profile: every column with its physical type, `required` from the
measured null rate, the grain as a `primaryKey` set plus the
error-severity grain rule, the quality rules that state what you
measured, and the `customProperties` block with `proposedBy: human`,
the profile's content hash as `profileHash`, `sourceLineage`, `vintage`,
and a `decision*` property for every judgment (rows dropped, flags
derived, units). The purpose, usage, and limitations paragraphs are
what the serving layer will hand an agent as `expert_context`: write
them for the person who will ask the question, not for the parser.

    uv run datacontract lint contracts/silver_<dataset>.odcs.yaml

Write `transform/models/silver/silver_<dataset>.sql`: one typed SELECT
over `{{ source('bronze', '<dataset>') }}`, every column the contract
declares, `captured_at` carried from `_airbyte_extracted_at`, no rows
dropped unless the contract says so. Then let the adoption scan drive
the enforcement wiring ([docs/adoption.md](adoption.md)):

    uv run dbt build --project-dir transform --profiles-dir transform --target local --select silver_<dataset>
    make scan

The queue reads `needs_profile`: add `{schema: silver, table:
silver_<dataset>}` under `profiling.targets`, run
`make profile ONLY=silver.silver_<dataset>`, and re-scan. It reads
`unenforced`: sync creates the properties file from the contract
(F-27) and `enforce-properties` adds the two keys sync omits:

    uv run datacontract dbt sync contracts/silver_<dataset>.odcs.yaml --project-dir transform --target local
    make enforce-properties TABLE=silver_<dataset>
    uv run dbt build --project-dir transform --profiles-dir transform --target local --select silver_<dataset>
    uv run datacontract dbt test contracts/silver_<dataset>.odcs.yaml --project-dir transform --target local
    make scan

Sync also writes the contract's SQL rules as singular tests under
`transform/tests/datacontract_cli/silver_<dataset>/`; review them like
any generated code (rule 11) and delete an `accepted_values: [0]` test
on sight (F-05). The build enforces the contract's shape, the test
line reads `dbt tests passed`, and the scan no longer lists the table.

A source that shares an entity with another source declares it here:
`conformedKeys: <column>=<key>` on each silver contract that carries
the key, an error-severity rule holding the column to the key's regex,
and the key's rule in the star contract's `conformedKeyRules`. The K1
gate (`tests/test_conformed_keys.py`) holds the declarations to each
other and refuses a key with one carrier, an undeclared key, or a
column without its rule, each by name. A unified table that settles
joins across sources is human-owned SQL under its own contract with
structured `joins` and measured completeness; `silver_flights` is the
pattern.

## 4. Gold: the mapping contract and the star

The mapping contract declares how the silver table becomes a category:
with a key, `make propose-mapping TABLE=silver_<dataset>` drafts it;
without one, copy `contracts/gold_airport_weather_mapping.odcs.yaml`
to `contracts/gold_<category>_mapping.odcs.yaml` and set the category
name, `sourceTable`, `timeColumn`, `timeGrain`, the grain (transaction
with a derived identity over the silver grain tuple, or aggregated),
and a `mappingRole` per field (dimension, measure, time). The
`profileHash` is the silver profile's content hash. Lint it, list it:

    uv run datacontract lint contracts/gold_<category>_mapping.odcs.yaml

Add the path under `engine.mapping_contracts` in `config/default.yaml`.
Then render the category's three star objects and paste them into the
star contract:

    uv run python scripts/render_star_objects.py contracts/gold_<category>_mapping.odcs.yaml > /tmp/star_objects.yaml

The output is the values dimension, the columns dimension, and the fact
with their conservation rules, in the star contract's own indentation,
followed by one `UNION` line. Paste the three objects into
`contracts/gold_unified_event_star.odcs.yaml` before the
`context_registry` object, add the `UNION` line to the C3 registry
coverage rule beside the other columns dimensions, and bump the star's
`version` (a minor bump: the change is additive). The pattern gate in
the unit lane holds the pasted objects to the render, so a hand edit
inside them fails by name.

    uv run datacontract lint contracts/gold_unified_event_star.odcs.yaml
    make context
    make regen

`make context` mints the next compiled-context artifact over every
contract; `make regen` emits the category's ten files (the dimension
pair, the fact, the typed mart and view, and their properties files)
beside the refreshed set and updates the ownership manifest. Refresh
the emission oracle, which the unit lane holds byte for byte:

    rm -f tests/golden/emitted/*.sql tests/golden/emitted/*.yml tests/golden/emitted/*.json
    cp transform/models/gold/*.sql transform/models/gold/*.yml transform/models/gold/ownership-manifest.json tests/golden/emitted/
    git diff --stat tests/golden/emitted

The star bump retires the previous version's generated tests and sync
writes the new ones (F-48):

    git rm -q -r transform/tests/datacontract_cli/gold_unified_event_star
    uv run datacontract dbt sync contracts/gold_unified_event_star.odcs.yaml --project-dir transform --target local

## 5. The proof: a cold build, the gates, the served category

Build from an empty warehouse, exactly as CI does, with the parse cache
removed (F-51, F-53):

    rm -f warehouse/metricmine.duckdb warehouse/metricmine.duckdb.wal && rm -rf transform/target
    make ingest
    uv run dbt build --project-dir transform --target local
    uv run datacontract dbt test contracts/*.odcs.yaml --project-dir transform --target local
    make audit-gold
    make export-demo
    uv run python scripts/check_demo_digest.py
    uv run ruff check . && uv run pytest -m "not local" -q && uv run pytest -m local -q

Every count grows by the category's own nodes and nothing else. In the
worked example the build went from `PASS=334` to `PASS=389`, the audit
from 67 to 83, gate 3 to `Tested 15 contract(s): 4 no tests · 11
passed.` (a mapping contract has no model by design), and both pytest
lanes stayed green once the oracle was refreshed. Then ask the served
layer:

    uv run python -c "from metricmine.query import GoldWarehouse; w = GoldWarehouse('warehouse/metricmine.duckdb'); print([(c['category'], c['row_count']) for c in w.list_fact_categories()['categories']])"

The new category lists with its subject and its registry keys, its
`expert_context` is the contract's own words, and its typed mart
answers a question in one statement. For the worked example: the
United States carried 25.95 percent of world GDP in 2023, from
`mart_world_gdp_typed` with `is_aggregate` filtered, a fact the context
had told the agent to filter.

## 6. What to commit, and in what order

Separate pull requests, contracts first (rule 6): the fetch script, the
extract, the README, and the bronze declarations; the silver contract;
the silver model with its properties, its generated tests, and its
profiles; the mapping contract; the star amendment with its generated
tests and the compiled context; the regeneration with the oracle, the
manifest, and the typed surfaces. The demo artifact never enters git
(D-03 as amended): `make export-demo` refreshes the committed manifest
and the artifact ships with the next release.

## Where the process pushes back, on purpose

- The fetch script refuses raw bytes with any digest but the pinned
  one; the samples gate refuses an extract whose README states another
  digest.
- The scan names the exact next command at every state and never lets
  a contract be weakened to pass a gate (rule 6, D-08).
- The K1 gate refuses conformed keys that are decoration: one carrier,
  no rule, no star declaration.
- The pattern gate refuses a hand edit inside a rendered star object.
- The emission oracle refuses a regeneration that was not reviewed into
  the fixtures, and the engine refuses to regenerate over a hand-edited
  emitted file, naming it (rule 8).
- The typed surface lowercases string values (D-18 Amendment M): write
  literals in lowercase, as the registry and the server instructions
  say.
